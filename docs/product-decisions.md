# 电商售后智能体｜一页产品判断说明

**定位：** 单渠道服饰退货 MVP，验证“能答、会问、知道停、可复盘”。  
**验收更新：** 2026-10-28｜ERNIE-5.1，经 LiteLLM 调用。

## 1. 场景裁剪：先验证一个完整闭环

只覆盖一个虚构商城、一类服饰、一套12条政策和5个模拟订单。只做政策问答、授权查单、信息追问、转人工四件事；退款、物流拦截等实际执行留给外部系统。这样能在短周期内验证业务判断与风险控制，降低多渠道政策差异和真实系统接入带来的干扰。

## 2. 决策分工：规则守边界，模型提证据

政策按“一条一 chunk”组织，以 P01–P12 追溯来源。检索使用 TF-IDF 相似度；模型提取检索政策的 ID 与原文证据，经程序校验后，由服务端模板结合订单事实生成业务回复。

| 边界 | 产品判断与实现 |
|---|---|
| 金额 >500元 | 演示业务设定，并非平台通行标准。500元整不触发；以实付与申请金额的较大值、按整数分判断，在调用模型前强制转人工并创建模拟工单，不承诺退款结果。 |
| 检索 top1 <0.6 | 保守的初始相似度门槛，不代表60%正确概率。低分只追问，禁止生成政策细节；后续需用独立口语样本校准，不能为提高成绩随意降阈值。 |
| 投诉／无明确答案 | 投诉先转人工；无答案明确无法确认并提供人工入口。订单查询校验演示身份，拒绝越权。 |

金额和检索门控放在代码层，是为了让模型表达变化或用户干扰不能覆盖业务约束。提示词仅约束证据提取格式。

## 3. 真实失败：金额消歧与多轮信息衔接

用户先说“ORD-1001 退我一些钱”，再补“1000元”。初版将“一些钱”误解析为1元，追问了退货原因，下一轮未接回金额，漏掉高金额转人工。

修复为拒绝模糊金额、保留待补金额槽位，并增加多轮回归；同输入回放后，先追问明确金额，再由1000元触发 R1 并建单。**这次失败没有直接承诺退款，也不是 E08 失败。** [原始前后记录](../reports/failure-amount.json)可核查。

## 4. 验收：安全行为与证据一起检查

固定15条用例：正常4、信息不足3、高风险4、无答案4；校验动作、引用来源、订单工具与工单真实性。界面同步展示对话、服务端决策轨迹和政策卡，保留每轮历史与失败判据。

ERNIE 曾出现 E02 超时，首轮14/15；调整请求预算后复测通过。随后同配置连续三轮均15/15，合计45/45、执行错误0；其中真实模型证据生成12次，耗时中位数10.31秒、最长16.48秒。其余用例主要验证代码门控，不能宣传为45次模型生成。[稳定性报告](../reports/stability-523a0286b5df4bb3b1100eec96d897bf.md)

## 5. 局限与下一步

订单、身份、工单均为模拟；无真实退款、物流、库存、人工队列或图片凭证识别。固定用例与三轮小样本不能证明开放场景安全，也未验证节省人工的实际收益。下一步优先补独立口语、多轮、金额边界及干扰输入评测，再考虑接入真实渠道。
